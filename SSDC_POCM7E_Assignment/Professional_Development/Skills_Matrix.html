Professional Skills Matrix

Module: Secure Software Development (SSDC_PCOM7E)

This skills matrix reflects the competencies demonstrated during the SSDC_PCOM7E module. The focus is on secure software development, including risk awareness, testing, implementation discipline and architectural reasoning.

Skill Evidence from Module Current Level Reflection
Security Risk Awareness Unit 1 – SQL injection flowchart and CD1 Advanced Demonstrated the ability to model how vulnerabilities emerge from development decisions. The activity diagram shows that weaknesses such as SQL injection result from cumulative design and review failures rather than a single coding error.
Secure Design Reasoning Unit 1 – UML activity diagram and design discussion Advanced Applied structured modelling to represent secure and insecure paths, including validation, parameterisation and review stages. This strengthened the ability to reason about security at design level rather than only at implementation level.
Vulnerability Analysis Unit 3 – Language comparison (C vs Python) Advanced Analysed how programming language characteristics influence vulnerability exposure. Demonstrated understanding that memory safety issues are rooted in architectural design, not just developer mistakes.
Input Validation & Attack Surface Awareness Unit 4 – Regex and ReDoS analysis Advanced Developed a more detailed understanding of how input validation mechanisms themselves can introduce vulnerabilities. The analysis of ReDoS showed that validation logic must be evaluated not only functionally but also in terms of computational behaviour.
Testing as a Security Control Unit 5 – Equivalence partitioning and boundary analysis Proficient Applied structured testing techniques to identify edge cases and boundary conditions. Recognised that testing contributes to security by reducing the likelihood of untested execution paths rather than guaranteeing absence of vulnerabilities.
Code Quality & Static Analysis Unit 6 – Linters and Python analysis tools Advanced Used static analysis tools to improve consistency and detect potential issues early. Understood the limitations of automated analysis, particularly in relation to context and business logic vulnerabilities.
Secure Implementation Unit 9 – Flask API with validation and access control Advanced Implemented a structured API with input validation, predictable behaviour and basic access control. Demonstrated the ability to translate secure design principles into working code while recognising limitations such as lack of persistence and advanced authentication.
Distributed Systems Awareness Unit 10 – Distributed systems and architectural discussion Proficient Developed a clearer understanding of how distributed architectures introduce additional security considerations, including communication trust boundaries, monitoring challenges and increased attack surface across services.
Critical Reflection Reflection document and Unit 3–4 analysis Advanced Reflected on the shift from a purely technical view of security towards a broader understanding that includes design, process and system behaviour. Demonstrated the ability to evaluate personal assumptions and refine professional judgement.
