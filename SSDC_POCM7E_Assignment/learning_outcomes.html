Learning outcomes

Module code: SSDC_PCOM7E

This page maps my module activities and artefacts to the formal learning outcomes of SSDC_PCOM7E (Secure Software Development). It demonstrates how secure coding, testing methodologies, programming language analysis and reflective evaluation collectively evidence achievement of the module outcomes.

Unit 1 – Secure SDLC and Risk Culture (LO1, LO4)

Learning Outcome: Secure Development Lifecycle Integration

Drawing upon more than 25 years of professional experience in software engineering, this unit prompted a critical reassessment of how security is embedded within the Software Development Life Cycle. While security considerations have always been present in my professional work, the structured academic framing clarified that secure software is not the outcome of individual technical decisions alone, but of deliberate lifecycle integration.

Through analysis of predictive and adaptive development approaches, I reflected on how risk awareness, early threat consideration and structured review processes influence vulnerability reduction. This activity demonstrates Learning Outcome 1 through identification and evaluation of development risks, and Learning Outcome 4 through reflective integration of professional experience into academic analysis.

Unit 2 – Modelling, Testing and Secure Design (LO2, LO3)

Learning Outcome: Secure Design and Validation

Engagement with modelling techniques and testing frameworks strengthened my understanding of how verification and validation operate as preventive security controls. Rather than viewing testing purely as quality assurance, I analysed testing as a mechanism for enforcing boundary conditions, validating assumptions and detecting unintended behaviour.

Applying structured testing approaches highlighted the importance of explicitly defining expected behaviour, particularly in relation to edge cases and malformed input. This activity evidences Learning Outcome 2 through critical analysis of development methodologies, and Learning Outcome 3 through application of secure program design and evaluation principles.

Unit 3 – Programming Languages and Memory Safety (LO1, LO2, LO3)

Learning Outcome: Vulnerability Analysis and Secure Implementation

The comparative exploration of buffer overflow in C and boundary enforcement in Python provided a practical illustration of how language design influences vulnerability exposure. Although memory safety vulnerabilities are technically familiar from prior experience, the structured comparison clarified the distinction between unmanaged memory models and managed runtimes.

The exercise demonstrated that vulnerabilities such as buffer overflows arise not merely from developer error, but from architectural characteristics of programming languages. Modern operating system mitigations (e.g. ASLR, DEP) reduce exploitability but do not eliminate underlying memory corruption. This reinforced my understanding that secure software requires preventive coding discipline, informed language selection and layered defensive controls.

This unit evidences Learning Outcome 1 through vulnerability identification, Learning Outcome 2 through analytical comparison of language paradigms, and Learning Outcome 3 through evaluation of secure implementation practices.
